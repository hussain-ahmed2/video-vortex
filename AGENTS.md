# Video Vortex

A Chrome extension (Manifest V3) that sniffs media on any page and offers it as a one click download.

## Stack

- **Language / Runtime**: TypeScript 6, no server and no Node runtime when the extension runs
- **Framework**: React 19 on Vite 8, built as three separate entry points (popup, service worker, content script)
- **Key dependencies**: Tailwind CSS v4, shadcn/ui (radix-nova style, on `radix-ui` and `@base-ui/react`), Motion, lucide-react, zod 4
- **Package manager**: npm (`package-lock.json`)

## Build approach

Tracer Bullet (each capability is built end to end through the worker, the content script, the popup and its tests, and works, before the next one starts).

## Commands

```bash
# Install
npm install
# Popup only dev server, background and content scripts do not hot reload
npm run dev
# Build, then load dist/ through chrome://extensions with Developer mode on, and
# reload the extension there after every rebuild
npm run build
# Lint
npm run lint
# Test: Vitest, configured inside vite.config.ts. Colocated tests, jsdom only where a
# file asks for it. 243 tests across 16 files
npm test
# One file, while iterating on it
npx vitest run src/design-language.test.ts
```

## Rules

- `public/manifest.json` is the contract with Chrome. It points at `background.js` and `content.js` by flat name, so renaming those two build inputs breaks the extension silently.
- Call the global `chrome.*` API directly. Both the promise style and the callback style appear in the code, match whichever the surrounding code uses. `webextension-polyfill` sits in devDependencies but never runs.
- An async `chrome.runtime.onMessage` listener must `return true`, or the response channel closes before the answer arrives.
- Type only imports need `import type`, because `verbatimModuleSyntax` is on in `tsconfig.app.json`.
- Shared shapes live in `src/lib/schemas.ts`. The zod schema is used for its type only through `z.infer`, nothing validates data with it yet, so do not assume any payload was checked.
- The primitives in `src/components/ui/` are generated by shadcn. Keep them as generated unless a change was asked for, and add new ones through the shadcn skill or CLI so the radix-nova style holds.
- Styling is Tailwind v4 with a CSS first config in `src/index.css`. There is no `tailwind.config.js` and theme tokens sit in `@theme`.
- `@theme { --color-*: initial }` in `src/index.css` deletes every default colour utility from the build, so a raw palette value compiles to nothing instead of erroring. The failure is silent by design, and `src/testing/guards/design-tokens.ts` is what makes it loud. That guard runs inside `npm test`, so a raw colour fails the build.
- The popup is dark by convention, unconditionally: the palette sits on `:root` and the popup needs no class on `<html>`. It paints from the theme tokens rather than from hardcoded utilities, so match that look rather than introducing light mode colors. A light theme later means moving that one block under `.dark`; nothing else about the structure changes.
- Comment the why, not the what. A comment earns its place only when the code cannot be read to learn it: a platform trap, a non obvious constraint, or a decision and its reason. Each module in the engine spec's module layout opens with a short header, one or two lines, saying what it owns and why it exists. Files in `src/components/ui/` stay as generated.
- Code under `src/engine/` is pure: no `chrome.*` call at run time, only type imports. Effects go through a port or a message. The rules are in `docs/specs/0001-detection-engine-architecture/`, and the engine does not exist yet, so slices build it.
- `dist` is gitignored, never commit build output. Commits follow Conventional Commits, as the existing history does (`feat:`, `docs:`).
